# frontend-design（Anthropic 官方）

上游：https://github.com/anthropics/skills（`skills/frontend-design/SKILL.md`）
作者：Anthropic · 许可以原仓库为准
用途：写代码前把设计计划写成可评审的 6 行，并避免三种"模型默认长相"。

## 何时读

- 要从零做一个页面或界面；
- 产出看起来"对但没记忆点"；
- 需要在动手前给用户看方案。

## 四步流程

1. **Ground in the subject**：从主题本身取材（行业、材料、工艺、场景），不从组件库取材。
   先问"这个产品最独特的三个事实是什么"，让版式从事实长出来。
2. **Plan**：写四要素再写代码——
   - Color：4–6 个**命名** hex（基础色、墨色、强调色、表面色、2 个状态色）；
   - Type：字族与各自角色（展示 / 正文 / 数据）；
   - Layout：一句话概念 + ASCII 线框（用来比较两个骨架，而不是直接写 CSS）；
   - Principles：这一页凭什么独特（3 条以内）。
3. **Build**：按计划实现，中途不擅自换方向。
4. **Critique**：对着 brief 逐条批，不通过就改计划而不是加装饰。

## 三种模型默认长相（明确点名要避）

- 米色/暖米底 + 高对比衬线大字 + 陶土色强调（"手工生活方式"默认款）；
- 近黑底 + 单一酸性绿或朱红强调（"AI 工具"默认款）；
- 报纸式排版：零圆角、极细分隔线、密排多栏、超大报头（"编辑风"默认款）。

任何一款套到同类产品上都成立，就说明没有做决定。

## 克制与微排版禁忌

- 不要只强调标题里的一个词（斜体/加粗/变色一个词）——这是最廉价的"设计感"。
- 不要用小号全大写 + 宽字距的装饰标签；标签必须有信息。
- 不要在内容上方加无意义的 kicker（"我们的优势"这类）。
- 大胆只花一处；其余保持安静。删掉一个你说不清理由的元素。
- **去装饰不等于完成**：拆掉卡片与标签后，必须用更大的字、更整的色块、真实的图补上，否则页面会读起来"空"。

## 界面文案

动词开头、第二人称、具体（"保存 API 密钥"而不是"继续"）；错误信息写清问题 + 下一步；
数字用阿拉伯数字；空格受限时用 `&`。
