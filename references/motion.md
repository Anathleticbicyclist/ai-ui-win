## 一、动效是结构，不是装饰

- 动效必须承载信息：表达层级、因果、空间连续性、状态变化。说不出它在传达什么，就删掉。
- 全页只允许一次"大编排"（页面加载或首屏揭示）。其余动效降级为局部、短促、可预期。
- 同一页面不要给每个元素都加动画——散点动效比没有动效更像 AI 生成。
- 动效强度要和设计方向一致：极简方向用 150–250ms 的克制过渡；沉浸式方向才允许编排级入场。

## 二、入场与编排

- 结构：标题 → 正文 → 图片/主视觉，按 60–90ms 阶梯延迟，位移 16–32px + 透明度 0→1，只触发一次。
- 首屏前必须解决"空白屏幕"：轻量预加载（字体、首屏图、模型），用分屏揭示、缩放或文字扫入撤场；不要留纯黑/纯白空屏等资源。
- 标题按词或按字符拆成可编排单元（`span` 包裹），但保留语义可读性（拆完仍是完整句子，屏幕阅读器读整句）。
- 层级对比要极端：展示级字号可用 `clamp()` 上探到 8–12vw，正文 16–18px。

## 三、滚动叙事

- 使用滚动进度驱动动画（GSAP ScrollTrigger / Motion 的 scroll 能力）时，必须可逆、可跳过，且不劫持滚动速度到失真的程度。
- 钉住容器（pin）只用于一次真正的叙事节点，不要每屏都钉。
- 横向位移只用于画廊、时间线一类天然连续的序列；移动端优先改为纵向堆叠。
- 视差只给背景层、中景文字、前景图各一档速度，且幅度小于一屏的 15%。

## 四、微交互

- 光标即用户化身：磁性按钮、自定义光标跟随（lerp 插值）仅在 `@media (hover: hover) and (pointer: fine)` 内启用。
- 悬停要有维度感：`scale`、`rotateX`、`translate3d`，而不是只换颜色。
- 导航：滚动向下隐藏、向上浮现；悬停可展开富内容，但键盘聚焦必须同样可展开。
- 状态切换必须有反馈：加载中、成功、失败、禁用四种态都实现，不用 0ms 瞬时切换。

## 五、性能红线

- 只动 `transform` 和 `opacity`。`width` / `height` / `top` / `left` / `margin` 的动画一律禁止。
- `will-change` 只加在确实会动的复杂元素上，动画结束移除。
- 长时间运行的动效组件要能暂停；离开视口即停。
- 图片用 WebP/AVIF，预留尺寸（CLS < 0.1），首屏外懒加载。
- 长列表（>100 项）虚拟化；输入防抖 200–300ms。
- 触屏设备降级：重动效、光标特效、大视差全部在触摸环境下关闭（用媒体查询判断，不要用 UA）。

## 六、可访问性兜底

- 所有动效必须包在 `@media (prefers-reduced-motion: no-preference)` 内；减动效模式下内容完整可见、位置正确。
- 不允许闪烁频率 >3Hz 的动画；不允许无限循环的强对比闪烁。
- 动效不得遮挡标题、正文或交互控件；不得让内容只在动画结束后才可见（渲染时机，而非透明度）。
- 键盘焦点在动画过程中不得丢失或跳位。

## 七、技术栈落地

| 目标 | 推荐 |
| --- | --- |
| React / Next.js | Motion（原 Framer Motion）做布局过渡与弹簧；Lenis 平滑滚动；3D 用 React Three Fiber |
| 原生 HTML / Astro | GSAP 时间线 + ScrollTrigger；Lenis（CDN）；SplitType 拆字 |
| Vue / Svelte | 优先原生 CSS transition + 各自生态的 motion 库，避免为动画引入重型依赖 |
| Android / iOS 原生 | 用平台动效 API（Compose animation / UIKit UIViewPropertyAnimator），不做 JS 式编排移植 |

引入任何动画库前先检查依赖文件；能用 CSS 完成的不引入库。

## 八、动效分级（先分级再实现）

参考 emilkowalski/skill 的动效取舍与 pbakaus/impeccable 的 animate 命令：

| 级别 | 目的 | 时长/形式 | 允许出现 |
| --- | --- | --- | --- |
| L1 反馈 | 让操作有回应 | 120–200ms，纯透明度/位移 | 所有界面，必须有 |
| L2 过渡 | 表达结构变化 | 200–350ms，共享元素/布局位移 | 所有界面 |
| L3 揭示 | 建立叙事 | 400–900ms，阶梯入场 | 营销页、首屏 |
| L4 编舞 | 制造记忆点 | 滚动驱动、钉住、横向叙事 | 只在一个界面的一处 |

- 应用界面只做到 L2；L3/L4 属于 Persuade / Experience 类页面。
- 判断升级是否值得：能否说出"这段动效帮用户理解了哪件事"。说不出，退回 L1。
- 直接操作（拖动、滑动、下拉）用弹簧；被动揭示用缓动；两者不要混在同一次交互里。
- 代码层同样要手感到位：不在渲染循环里逐帧读布局，不重复创建动画实例，卸载时清理监听。
