# 艺术方向与设计系统（Art Direction）

融合自 Leonxlnx/taste-skill v2 与 Anthropic frontend-design 的核心方法：先读 brief、先定方向与 token、
再写代码；用"是否有决定"而不是"是否好看"来评判产出。

## 一、先读 brief（不发明需求）

动笔前确定五件事，缺的用一句话写下你的判断，不要反问一堆：

1. **行业/品类**：这是哪一类产品，同行默认长什么样（知道默认才能偏离默认）。
2. **受众**：谁在用，什么场景（通勤手机、工位大屏、会议投屏）。
3. **情绪**：可信 / 锋利 / 温暖 / 精密 / 张扬——选一个形容词，不要三个都想要。
4. **图像现实**：有真实照片/产品截图/可用图库，还是只能靠排版与色块。
5. **成功动作**：这个界面要让人做成的**一件事**（注册、下单、导出、看懂）。

> 若需求本身模糊：**做一个判断并写出来**，比连问三个问题更专业。除非涉及品牌资产、必须保留的功能、或用户才能提供的素材。

## 二、三种"AI 味"陈词滥调（命中即改）

当前模型产出高度聚簇于三种长相，它们对某些 brief 是成立的，但多数时候只是默认答案：

1. **米色暖底（≈ #F4F1EA）+ 高对比衬线标题 + 陶土色强调**——"生活方式品牌"默认款。
2. **近黑底 + 单一高亮酸性绿或朱红强调**——"AI 工具/加密"默认款。
3. **报纸式版式：极细分隔线、零圆角、密排多栏、超大衬线报头**——"编辑风"默认款。

判定方法：**把这个配色与版式套到任何一个同类产品上，如果也完全成立，那它就是默认答案**，需要换掉其中至少一个维度（字族、底色、强调色位置、版式骨架、图像处理）。

另外禁止把"高级感"等同于"加装饰"：渐变光晕、玻璃拟态、发光描边、悬浮阴影四件套同时出现，是最典型的模板信号。

## 三、三个旋钮

在动手前显式声明三个 1–10 的数值，写进你的方案第一行。默认值：

| 旋钮 | 默认 | 低（1–3） | 中（4–7） | 高（8–10） |
| --- | --- | --- | --- | --- |
| 布局变化 `variance` | 8 | 居中、对称、极简网格 | 常规现代版式 | 非对称、破格、编辑式 |
| 动效强度 `motion` | 6 | 仅 hover/状态过渡 | 入场阶梯 + 滚动揭示 | 编舞级：钉住、横向位移、视差 |
| 信息密度 `density` | 4 | 宽敞营销页（24–96px 间距） | 标准（16–64px） | 密集后台（8–32px） |

规则：
- 后台/工具类把 `density` 提到 7–8，把 `motion` 降到 3–4；营销页反过来。
- `variance` ≥8 时才允许打破栅格；破格必须在栅格内破，外边距仍成对相等。
- 旋钮只调这三轴，不改变方向本身。

## 四、Brief → 设计系统映射

先问"这个 brief 有没有现成的正确系统"，再决定自研：

| 场景 | 优先采用 | 何时改用原生 CSS/自研 |
| --- | --- | --- |
| 企业内部工具、Office 生态 | Fluent | 需要与既有品牌强绑定 |
| 跨平台产品、Android 优先 | Material 3 | 需要独特视觉人格 |
| 金融/企业级后台 | Carbon / Polaris | 交互复杂度低于其预设 |
| 设计系统已存在（Radix / Primer） | 直接用，不自造 | 无障碍要求超出其覆盖 |
| React 产品快速搭建 | shadcn/ui + Tailwind | 需要非 Tailwind 的样式方案 |
| 单页、活动页、作品集 | 原生 CSS | 需要组件库的复杂交互时 |

不自研系统的理由只有一个：**现成系统能覆盖 80% 以上，且不与你需要的人格冲突**。若冲突，只在 token 层替换（色、字、圆角、阴影），不重写组件行为。

## 五、暗色模式协议

- **默认双模式**，除非产品明确只做单模式；先定亮色，再推导暗色，而不是把亮色反相。
- 用语义 token（`--surface` / `--ink` / `--border` / `--accent`），两套主题只换值，不换结构。
- 暗色不用纯黑（#000），亮色不用纯白（#FFF）；用近黑 #0B0B0C 与暖白 #FAFAF8 一类。
- 两套模式的**层级关系必须一致**：亮色靠阴影分层的，暗色改用色阶提亮，而不是加深阴影。
- 对比度不因主题降级：正文 ≥4.5:1，大字 ≥3:1，边框这类非文本 ≥3:1。
- Web 端 `color-scheme` 与 `theme-color` 跟随主题；原生 `<select>`、滚动条、输入框要显式设色。
- 图片/插画在两套模式下都要检查：透明 PNG 在暗色下常出现脏边。

## 六、Token 先行（写代码前的 6 行）

frontend-design 的核心做法：先写设计计划，再自我批判，最后才写代码。

```
palette:  4–6 个命名色（ground / ink / accent / surface / 2 个状态色）
type:     展示字族 + 正文字族 + 5 级字号 + 展示/正文比（≥3）
layout:   一句话骨架（单栏 / 非对称双栏 / 破格叠压 / 密排多栏）
signature: 这一页唯一会被记住的元素（1 个，不是 3 个）
motion:   variance / motion / density 三个数值
risk:     一个你能说出理由的审美冒险
```

写完先自问三句，任何一句答不上就重写计划：
1. 这套 token 换成任何同类产品还成立吗？（成立 = 默认款）
2. 去掉装饰后，页面还靠什么撑住？（答案只能是：字够大、色块够整、图是真的）
3. 记忆点是"元素"还是"效果"？（效果类记忆点最容易显得廉价）

## 七、克制原则：只花一次大胆

- 大胆只花在一个地方（signature），周围保持安静、 disciplined。
- 香奈儿法则：出门前照镜子，摘掉一件配饰。页面上同理：删掉一个你想要但说不清理由的元素。
- **去装饰不等于做完**：拿掉了标签、分隔线、卡片，却没有用更大的字、色块、真图补上，页面会读起来"空"。
  空比"有瑕疵但充实"更差。
- 每屏都应当是"一张海报"：一个主导元素 + 它承载的内容；连续两屏接近空白就是不达标。

## 八、重设计协议

改造既有界面时，禁止直接重画。顺序是：

1. **记录现状**：跑起来截图（三档宽度），读代码（框架、样式方案、必须保留的路由/表单/数据）。
2. **先评审后动手**：只做评审时到此为止，输出问题清单 + 三个最能改变观感的改动。不定方向、不写代码。
3. **保留可用的**：不迁移框架、不换样式库、不动品牌资产。保留内容、行为、数据结构。
4. **按收益排序改**：字型与字号 → 色彩（一底一墨一强调）→ 版面框架（边距、节奏、标题层级）→ 状态（hover/focus/loading/empty/error）→ 最后才替换"图标卡片 / 胶囊标签 / 渐变光斑 / 卡片墙"这类模板构件。
5. **用证据收尾**：改完再截一次，前后并排看；原来能点的链接、能提交的表单必须仍能点。

重构与重设计的区别：**重构保留现有视觉身份，只提精度；重设计把旧视觉当作反参考，换掉整套方向**。不要在"要丢掉的旧风格上做抛光"。
