# 方案探索与收敛（Explore → Converge）

方向不确定时，不要凭空写一版就交付。方法参考 joinutlope/variate（多变体）、
superdesigndev/superdesign-skill 与 oil-oil/oil-ui（并排对比）、codeswithroh/tastemaker（参考图与品味档案）。

## 一、什么时候启动探索

- 用户只给了功能，没有给审美方向。
- 用户说"不好看 / 说不上来哪里不对 / 太普通"。
- 需要提案或比稿，交付物包含方案选择。

其他情况直接按 art-direction 定一个方向，不做探索。

## 二、三个变体，差异必须在结构层

- 数量 2–3 个，不要 4 个以上（超过三个就没有区分度，只会把选择成本丢给用户）。
- 变体之间必须差在**结构或色彩世界**，不能只换强调色：
  - A：单栏、超大标题、留白主导
  - B：非对称双栏、图主文辅
  - C：密排编辑风、分隔线与色块分区
- 每个变体配一句话说明它赌的是什么（"赌标题够大"、"赌图是真的"）。
- 同一个 token 集合可以共享，但版式骨架必须不同。

## 三、用截图对比，不用形容词对比

- 每个变体渲染到同一组尺寸（375 / 768 / 1440）后截图，并排看。
- 判断标准按顺序：① 是否说清了这个产品做什么 ② 记忆点是否成立 ③ 缩小到 30% 后层级是否还清楚 ④ 维护成本。
- 只凭代码判断版面一定出错；看不到渲染结果就不要下结论。

## 四、参考图法（品味档案）

- 收集 3–5 张真实参考（截图、竞品、海报），逐张写下**为什么它对**：字族、底色、强调色位置、版式骨架、图像处理。
- 提炼成 5–8 行的 taste profile，作为之后所有页面的约束。
- 只借鉴"决策"，不复制像素；不照搬整站布局、不复制 Logo、不搬版权图片。

## 五、收敛

- 选 1 个主方案 + 1 个备选，说明取舍理由（不是"更好看"，而是"更符合成功动作 / 更好维护"）。
- 落地的方案必须补齐所有状态（loading / empty / error / disabled），变体阶段允许只做静态主屏。
- 淘汰的方案不留代码，避免两套风格并存。
